# 4단계: 입 crop 범위와 기울기 정렬의 통제 비교

3단계와 같은 네 train 발화(`000006`, `000018`, `000027`, `000033`)를 사용한다.
이전 결과를 보고 발화를 교체하지 않는다. 입력 크기 96×96, 원본 FPS 25, CTC greedy를
고정하고, 입 주변 여백과 눈 기준 회전만 바꾸는 2×2 비교이다.

## 실제 결과 (2026-09-17)

| 조건 | 처리 성공 | 전체 CER (실패는 빈 예측) | 성공 항목만 CER |
| --- | ---: | ---: | ---: |
| 1.7배, 정렬 없음 | 4/4 | 82.76% | 82.76% |
| 1.3배, 정렬 없음 | 4/4 | 85.34% | 85.34% |
| 1.7배, 눈 기준 정렬 | 0/4 | 100.00% | 계산 불가 |
| 1.3배, 눈 기준 정렬 | 3/4 | 87.93% | 82.28% |

기존 기준 조건의 네 발화 출력 토큰이 3단계와 완전히 일치했다. 1.3배 정렬은
`000027`의 60번째 crop 프레임에서 회전 여백이 들어와 실패했다. 1.7배 정렬은
네 발화 모두 여백 조건을 통과하지 못했다. 회전하기 전에 잘라낸 얼굴 영상에 충분한
주변 영역이 없다는 현 구현의 제약이며, 일반적으로 얼굴 정렬이 무효라는 결론이 아니다.

1.3배 정렬의 성공 항목 3개에 한정해 같은 ID끼리 비교하면, 정렬 없음 CER 86.08%에서
정렬 있음 82.28%로 낮아졌다. 그러나 실패를 포함한 전체 처리 성능은 더 나빠졌다.
모든 조건의 공통 성공 항목은 0개이므로 전체 공통 CER는 null이다. 조건 쌍별 비교는
유효한 동일 ID 집합에서 따로 계산했다.

**기본값은 96×96·25 FPS·crop 1.7배·정렬 없음으로 유지한다.** 네 발화에 반복적으로
맞춘 개발 비교이므로 최적 설정이나 일반화 성능으로 주장하지 않는다. 인식 정확도는 여전히 낮다.
추가적인 crop 조정만 계속하기보다, 다음에는 N-best 후보와 정답에 가장 가까운 후보의
CER(oracle CER)을 확인해 문맥 재정렬이 개선할 여지가 있는지 진단한다.

원시 수치·실패·선택 계획: [실험 JSON](../experiments/crop_2026-09-17.json).

| 조건 | 입 크기 배율 | 정렬 |
| --- | ---: | --- |
| scale17_none | 1.7 | 없음 (3단계 기준 조건 재실행) |
| scale13_none | 1.3 | 없음 |
| scale17_eyes | 1.7 | 양 눈의 바깥쪽 점을 수평으로 회전 |
| scale13_eyes | 1.3 | 양 눈의 바깥쪽 점을 수평으로 회전 |

배율은 입 랜드마크 바깥 경계의 가로/세로 중 큰 길이에 곱한다. 발화 내 크기 변화에 따른
확대·축소를 줄이기 위해 프레임별 크기의 중앙값을 정사각형 한 변으로 사용한다.
회전 조건에서는 랜드마크에도 같은 회전 행렬을 적용한 다음 crop 크기를 계산한다.
실제 source crop은 224×224로 만들고 모델 입력 단계에서 96×96으로 줄인다.

## 원래 모델의 전처리와 다른 점

공식 OLKAVS `preprocess.py`는 데이터셋이 제공하는 프레임별 `Lip_bounding_box`로 crop한다.
공식 `v_train.yaml`은 `architecture: video`, `raw_video: True`, `use_audio: False`를 명시한다.
반면 KMSAV ASD는 얼굴 좌표이므로 여기서는 MediaPipe로 입 좌표를 추가 추정한다.
따라서 이 실험은 원래 lip annotation을 재현한 것이 아니다. 공개 설정 파일을 다운로드한
체크포인트의 실제 학습 설정과 완전히 동일하다고 간주할 수도 없다.

기울기 보정은 화면 내 2차원 회전만 제거한다. 고개가 옆으로 돌아간 3차원 자세나 가려진 입을
복원하지 않는다. 원본 모델의 체크포인트·문자 사전·BGR 정규화·디코더는 네 조건에서 동일하다.
정답 전사와 음성을 모델 입력으로 사용하지 않는다.

## 실행

[2단계 환경](STAGE2.md)을 준비한 뒤 저장소 루트에서 실행한다.

```console
python -m kvsr.batch --suite crop --archive data/raw/kmsav_asd_v0.2.zip --catalog external/kmsav/data/list.txt --video-id 8r1k9NLdSvE --video data/raw/8r1k9NLdSvE.mp4 --model checkpoints/face_landmarker.task --checkpoint checkpoints/olkavs_multiview_lip.pt --repo external/olkavs --output results/crop_2026-09-17
```

개별 전처리에는 `--crop-scale 1.3 --align eyes` 옵션을 사용할 수 있다.
`--suite size-fps` 또는 suite 생략은 기존 3단계 비교를 실행한다.
같은 배율·정렬의 crop은 발화별로 한 번만 만들고 필요한 입력 크기/FPS 조건에 공유한다.

## 실패와 검증 규칙

회전 영상과 함께 유효 픽셀 마스크를 만든다. crop에 회전 여백이 한 픽셀이라도 들어오면
실패 처리한다. 검은 여백을 정상 입 영상으로 간주하거나 주변 픽셀로 임의 채우지 않는다.
회전 행렬·각도·crop 중심·경계 이동 여부를 프레임별로 저장한다. 정렬 조건의 `face.mp4`와
확인 이미지 위쪽에는 **정렬된 얼굴**을 표시하고 `face_preview_aligned`로 구분한다.

전체 선택 항목(실패는 빈 예측), 성공 항목만, 모든 조건의 공통 성공 항목의 지표를 별도로 계산한다.
정렬 조건에서 실패가 증가했다면 성공 항목만의 CER 개선을 곧바로 개선으로 해석하지 않는다.
`pairwise_comparisons`에는 두 조건씩 공통 성공 ID와 지표를 저장한다. 어떤 조건이 전부
실패해 전체 공통 항목이 없어지더라도 나머지 조건끼리의 유효한 비교를 확인할 수 있다.

추가 테스트는 회전 후 눈 높이 일치, 회전 여백 마스크, 수평 눈의 영상 불변성,
잘못된 눈 좌표 거부를 확인한다. 일부 조건이 전부 실패할 때의 조건 쌍별 비교도 검사했다.
로컬 의존성 환경에서 전체 27개 테스트를 통과했다.

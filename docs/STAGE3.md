# 3단계: 고정 발화의 기본 성능과 전처리 조건 비교

확보한 KMSAV 영상의 공식 train 발화 26개 중 **길이가 10초 이하인 4개 모두**를
실험 시작 전에 고정했다. 이 결과는 단일 영상의 개발 실험이며, 별도 test set의 성능이 아니다.
성공/실패나 인식 결과를 보고 발화를 교체하지 않았다. 길이 제한으로 제외한 22개도 plan에 기록한다.

## 실제 결과 (2026-09-17)

| 입력 크기 | FPS | 성공/선정 | CER | WER |
| --- | ---: | ---: | ---: | ---: |
| 96×96 | 25 (원본) | 4/4 | 82.76% | 100.00% |
| 96×96 | 30 | 4/4 | 84.48% | 97.56% |
| 224×224 | 25 (원본) | 4/4 | 96.55% | 100.00% |
| 224×224 | 30 | 4/4 | 96.55% | 100.00% |

대상 ID는 `000006`, `000018`, `000027`, `000033`이다. 총 정답 문자 116개, 어절 41개를
기준으로 계산했다. 16건 모두 성공하여 전체·성공 항목·공통 항목 점수가 동일하다.
네 발화의 확인 이미지에서 입 위치를 육안 확인했다.

224 입력과 30 FPS 변환만으로 정확도가 개선되지 않았다. 96×96·25 FPS 조건은 이후 개발
비교의 출발점으로 유지하되, 작은 개발 표본의 최저 CER을 일반적인 최적 설정이라고 주장하지 않는다.
지난 1개 발화의 68.42%와 이번 4개 발화의 82.76%는 평가 대상이 달라 직접적인 성능 하락 비교가 아니다.
이번에는 224 crop에서 96 입력을 파생했고, 지난 실행은 직접 96 crop을 만들었다는 차이도 있다.

원시 수치와 선택 계획은 [실험 JSON](../experiments/baseline_2026-09-17.json)에 있다.
다음은 crop 범위와 정렬 방식, 모델 학습 시의 실제 입력 조건을 추가 점검하는 일이다.
현재 높은 CER 상태에서 LLM을 붙인 개선을 곧바로 립리딩 성능 향상으로 해석하지 않는다.

## 원래 전처리와의 대조

OLKAVS commit `af2feda3e3ac91ff3fef2454fcee662366ce9f4b`의 `preprocess.py`는
lip bounding box와 기본 `resize_shape=(224,224)`, `fps=30`을 사용한다.
`dataset/dataset.py`의 raw-video loader는 OpenCV BGR 프레임을 영상 전체 mean/std로 정규화한다.
README의 96×96 설명과 코드의 기본값에 차이가 있으므로, **체크포인트의 정확한 학습 설정을
확인했다고 단정하지 않는다.** 출처: [공식 전처리 코드](https://github.com/IIP-Sogang/olkavs-avspeech/blob/af2feda3e3ac91ff3fef2454fcee662366ce9f4b/preprocess.py).

이번 비교는 동일한 MediaPipe 입 위치와 224×224 원본 crop으로 시작한다. 입력 크기를
96/224, FPS를 원본 25/30으로 바꾸는 네 조건을 모두 측정한다. 크기만 바뀌는 조건끼리,
FPS만 바뀌는 조건끼리 비교할 수 있다. 이 비교만으로 OLKAVS의 lip bounding box 생성 방식이나
촬영 환경 차이가 해소되지는 않는다. 낮은 해상도의 원본에서 224 crop을 만든다고 세부 정보가 복원되지 않는다.

## 실행

[2단계](STAGE2.md)의 데이터·체크포인트·가상환경을 준비한 뒤 저장소 루트에서 실행한다.

```console
python -m kvsr.batch --archive data/raw/kmsav_asd_v0.2.zip --catalog external/kmsav/data/list.txt --video-id 8r1k9NLdSvE --video data/raw/8r1k9NLdSvE.mp4 --model checkpoints/face_landmarker.task --checkpoint checkpoints/olkavs_multiview_lip.pt --repo external/olkavs --output results/baseline_2026-09-17
```

기존 결과 폴더는 덮어쓰지 않는다. 다시 실행하려면 새로운 `--output` 경로를 지정한다.
`--max-seconds` 기본값은 10이다. 범위를 바꿀 경우 다른 실험으로 취급하고 plan을 따로 보관한다.
현재 명령은 단일 train 영상만 허용한다. 데이터셋 전체 평가 명령은 아니다.

## 실험 기록

- `plan.json`: 예측 전에 저장하는 대상 ID·제외 사유·네 조건·데이터/가중치 해시.
- `references.jsonl`: 평가용 정답. 추론 프로세스에는 넘기지 않는다.
- `crops/<recipe>/<utterance>/`: 각 발화의 입 배열, 얼굴 미리보기, 프레임별 좌표.
  (최초 3단계 실행은 recipe 하위 폴더 없이 저장했다.)
- `<condition>/predictions.jsonl`: 조건별 전체 성공 예측과 추론 출처.
- `*.log`, `progress.json`: 작업 로그와 진행 상황.
- `summary.json`: 성공률, 실패 원인, 전체/성공 항목/공통 성공 ID의 CER·WER.

실패를 빈 예측으로 계산한 전체 수치는 **시스템 운영 관점의 점수**이다. 모델이 실제로
빈 자막을 출력한 것과 혼동하지 않도록 실패 사유와 성공 항목만의 점수를 함께 남긴다.
조건별 성공 항목이 달라지더라도 `paired_metrics`는 모든 조건에서 공통으로 성공한
동일 ID만 비교한다. CER/WER는 문장별 점수 평균이 아니라 전체 편집거리/전체 정답 길이이다.

## 메모리와 FPS 처리

CTC 추론은 OLKAVS의 시각 front-end를 48프레임 단위로 나눈다. 시간축 커널 폭 5에 맞춰
각 구간 양쪽의 2프레임을 함께 처리하고 중앙 특징만 연결한다. 모델은 eval 모드이다.
전체 시퀀스의 문맥을 사용하는 Conformer는 구간별로 나누지 않는다. 공식 front-end의
17프레임 입력에서 전체 처리와 구간 처리의 최대 차이가 0인 것을 확인했다.

30 FPS 조건은 프레임 중심 시각에 가장 가까운 원본 프레임을 선택한다. 중간 입모양을
합성하지 않는다. 길이는 출력 한 프레임 이내의 반올림 차이만 허용한다. 실제 선택한
입력 FPS·프레임 수·크기·파일 해시는 예측마다 기록한다.

## 검증

로컬 전처리·CPU 추론 환경에서 테스트 24개 통과. 추가 검사는 실패 누락 방지,
조건별 ID 일치, FPS 변환의 시간 유지, 구간 처리 경계의 수치 동등성을 확인한다.
의존성이 없는 환경은 해당 영상/PyTorch 검사를 skip한다. 실제 데이터 추론은 별도 로컬 실행으로 검증한다.

원본 영상·전사·모델은 로컬에 보관한다. 저장소에는 원본 텍스트를 제외한
집계 기록과 실행 계획을 `experiments/`에 남긴다.
